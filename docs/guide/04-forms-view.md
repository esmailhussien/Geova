# Module 04: Data Collection & Form Schemas

Geometry on a map is useless without the context of tabular attributes. Geova’s **Form Builder** allows you to attach a strictly constructed data entry template to any active layer. Every time a user draws a new point, line, or polygon in the Map Engine, this custom form acts as the gatekeeper, controlling exactly what data gets written to the permanent spatial database.

---

## 1. Setting Up: Importing an Existing Schema

Building an enterprise form manually from scratch can be tedious when you already have standardized enterprise data models.

### The "Why": Real-World Value
A telecommunications team is conducting a national utility pole inspection. They are federally required to record exactly 55 specific attributes for each pole. Manually rebuilding these 55 fields inside a mobile app introduces the risk of human typos (e.g., spelling `Condition_Status` as `Cond_Status`). Instead, the regional director simply taps **Import Schema** and uploads their standardized `.json` file, instantly configuring the exact 55 fields across every mobile device in seconds. 

### The "How": Step-by-Step
1. Select your target layer from the **Layer Selector** dropdown in the Form Builder workspace.
2. Click the **Import Schema** button (File Upload icon) located next to the Add Field button.
3. Select your `.csv`, `.json`, or `.geojson` file containing the headers you wish to import.
4. The system will automatically parse the headers and mount them as generic Text fields, ready to be refined.

## 2. Defining Attributes: Field Data Types

Different real-world scenarios require different programmatic data constraints to maintain database integrity.

### The "Why": Real-World Value
Consider a **Forestry Mapping Project** where rangers log diseased trees. If a worker is allowed to type "Pine", "pine", "p", or "Piney tree" into an open text-box, the underlying SQL analytics database will become completely fragmented. You must enforce constraints.

Here is how different field types achieve strict data hygiene:
*   **Text (Single Line):** Used for short, unpredictable strings like `Inspector Name`.
*   **Number:** Forces a strictly formatted float/integer, critical for analytics. Example: `Trunk Diameter (Inches)`.
*   **Dropdown (Options):** Used to restrict entry to a predefined list. Example: Constraining the `Species` field strictly to "Pine, Oak, Maple".
*   **Date picker:** Ensures standardized ISO datetimes for temporal layers. Example: `Date of Last Survey`.
*   **Checkbox (True/False):** Boolean logic. Example: `Is Infected with Bark Beetles?`
*   **Photo (Camera):** Captures the device's native camera stream. Example: A single evidence photo of the canopy.
*   **Gallery (Multiple Images):** Allows for multiple situational angles. Example: Documenting the tree's roots, trunk, and branches simultaneously. 
*   **Attachment (PDF/File):** Example: Attaching a digital copy of the required physical felling permit to the mapped feature.
*   **Auto-Geometry (Length/Area/Coords):** Read-only calculated metadata generated by Geova's engine. Example: Instantly displaying the calculated exact Latitude/Longitude of the tree.

### The "How": Step-by-Step
1. Tap the **Add Field** button.
2. Enter the **Field Label** (e.g., "Tree Species").
3. Click the **Data Type** selector and choose from the list.
4. (If Dropdown): Enter the strict list of comma-separated options.
5. Tap **Add Field** to commit the structure to the UI row.
6. When all fields are configured, click the large green **Save Form Schema** button at the bottom to deploy it to the database.

## 3. Forcing Data Quality: The "Required" Toggle

Field work is exhausting, and it is natural for tired technicians to skip fields when rushing to finish a job.

### The "Why": Real-World Value
An environmental response team is testing river water for toxic pH levels following an industrial spill. If a worker plots a test-site point but forgets to enter the actual pH number, the data is entirely useless and legally invalid. By toggling the **Required (Mandatory)** switch on the `Water_pH` field, the app will literally refuse to save the point geometry until the technician inputs a valid floating-point number.

### The "How": Step-by-Step
1. While configuring or editing a field, look for the checkbox labeled: **"This field is strictly required"**.
2. Tick the box. 
3. When the field is rendered in the row list, it will now display a red <span style="color:red;font-weight:bold;">*</span> indicator, denoting that database inserts will fail without this value.

## 4. Relational Intelligence: Spatial Reference Logic

Typing out geographic attributes that can automatically be derived from spatial intersections is a massive waste of operational time. 

### The "Why": Real-World Value
Imagine mapping 2,000 damaged street signs across a sprawling metropolitan city. The Public Works Department needs to know exactly which Political Voting District (`District_ID`) each broken sign belongs to for budget allocation. 
It is unreasonable to expect the field worker to memorize the invisible political district borders. Instead, you use **Auto-calculate from Spatial Reference**. When the worker pushes the button to log a broken sign, Geova instantly looks down through the map layers, detects which underlying `Voting_Districts` polygon the point fell into, extracts the `District_ID`, and explicitly writes it to the form invisible to the worker. 

### The "How": Step-by-Step
1. Ensure your reference polygon layer (e.g., Voting Districts) is loaded into Geova.
2. In the Form Builder, edit your target field (e.g., `District_ID`).
3. Check the box for **"Auto-calculate from Spatial Reference"**.
4. The Spatial Group panel will appear. In the **Reference Layer** dropdown, select your underlying polygon layer.
5. In the **Extract Property** dropdown, choose the explicit attribute you want to copy (e.g., the district number).
6. Save the schema. The `District_ID` field will now automatically populate itself during field collection based purely on GPS geometry intersections.

## 5. Smart Logic: AI-Assisted Form Rules (Simple Mode)

Forms become incredibly powerful when they adapt dynamically to the user's input. Smart Logic allows you to configure ECA (Event-Condition-Action) rules. The "Simple Mode" uses a natural language sentence builder, augmented by a Magic AI Prompt that lets you dictate rules in plain English.

### The "Why": Real-World Value
An environmental agency is building a field form for wildlife surveys. If the inspector selects "Bear" from the *Animal Type* dropdown, the form needs to instantly make the *Aggression Level* field mandatory, show the *Distance to Observer* field, and hide the *Bird Species* field. Instead of writing code, the admin types into the AI Bar: *"If Animal Type is Bear, require Aggression Level and hide Bird Species."* The AI instantly translates this text into structured form logic rules.

### The "How": Step-by-Step
1. Open the form builder and navigate to the **Smart Logic** panel.
2. Ensure the top toggle is set to **Simple**.
3. In the **AI Prompt Bar**, type your plain English rule (e.g., *"When Status is 'Complete', set the inspection date to today."*).
4. Tap **Generate**. The engine will securely interpret your intent and populate a rule card.
5. You can manually adjust the generated sentence by tapping the highly-interactive word pills (e.g., tapping `[Field]`, `[is/is not]`, or `[Value]`). 
6. Supported AI Actions include: **Show**, **Hide**, **Require**, and **Set Value**.

## 6. Writing Complex Logic Rules Manually (Advanced Mode)

For power users who need cascading, multi-conditional logic (Boolean logic with nested AND/OR operators), the Advanced Mode block builder handles logic structures that simple sentences cannot.

### The "Why": Real-World Value
A telecom company is calculating fiber optic cable costs based on the material type, the current installation zone, and the length of the geometry traced on the map. They need a rule: *IF (Zone == 'Urban' OR Zone == 'Suburban') AND (Material == 'Fiber'), THEN Set 'Total Cost' to [Geometry Length] × 1.45.* The Advanced block builder handles these nested OR groups effortlessly.

### The "How": Step-by-Step
1. In the Smart Logic panel, switch the top toggle to **Advanced**.
2. Click **Add Rule** (represented by a lightning bolt).
3. Under the **IF** section, choose a target field, an operator (e.g., `==`, `!=`, `<`, `>`), and a value.
4. Click **+ Add AND** to stack required conditions, or click **+ Add OR Group** to create an alternative testing pathway.
5. Under the **THEN** section, choose your action.
6. The rule engine validates your logic instantly; incomplete boundaries are highlighted in amber.

## 7. Binding Rules: Formulas and Dynamic Linking

The ultimate power of Geova Smart Logic is the **SET_VALUE** action, which allows you to bind form fields mathematically to other fields—or even to spatial attributes computed by the map engine (like Auto-Geometry lengths and areas).

### The "Why": Real-World Value
An agricultural inspector draws a polygon representing a damaged crop field. They don't want to guess the acreage. Using a Smart Logic Formula, they set up a rule: `Set the value of [Crop Damage Fee] to [Formula: Area in Acres * $500]`. Every time the inspector reshapes the map polygon, the cost is automatically re-calculated and written directly into the tabular form without lifting a finger.

### The "How": Step-by-Step
1. Construct your rule condition in the Smart Logic UI (e.g., *When 'Geometry Area' is > 0*).
2. Set the Action type to **Set Value** (or *Set the value of* in Simple Mode).
3. Target the destination field (e.g., `Estimated Cost`).
4. In the value section, rather than typing a static number, click the **Data Object Link** icon (<span class="material-symbols-outlined text-[14px]">data_object</span>).
5. You can now build a **Formula** (e.g., `Field A` × `Constant/Field B`) using the math operand picker (`+`, `-`, `×`, `÷`).
6. Save the Form Schema. These bound fields will now dynamically animate and calculate in real-time as field workers touch the map.
